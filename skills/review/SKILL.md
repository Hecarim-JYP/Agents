# 컨벤션 준수 리뷰

변경(diff)이 JYP 컨벤션·설계 원칙을 지켰는지 **읽어서** 검토한다. 범용 버그·단순화는 기본 /code-review, 계층 데이터 계약 추적은 /paper-test, 런타임 파괴는 qa-claude가 본다 — 이 스킬은 **린트가 못 잡는 판단 규칙**만 본다.

## 대상

- 기본: 현재 브랜치의 커밋되지 않은 변경 전체(`git diff HEAD` + untracked). "이번 세션에서 건드린 파일"만 보는 것 금지.
- 선택 인자: PR 번호 / 브랜치 / 경로 타깃.

## 무엇을 보나 (린트와의 경계)

- **제외**: ESLint·Checkstyle·post-edit-check 훅이 이미 강제하는 것(파일 헤더 `[박진영]`·`any` 금지·네이밍·포맷). 중복 지적 금지.
- **본다(판단 필요)**: 계층 분리·책임 배치(patterns.md) · 응답/에러 계약 형태(patterns.md 3절·api.md 5절) · 신뢰 경계 · 논리 FK·인덱스(database.md) · 동시성 제어 누락(sql.md 8절) · 성급한 추상화·3회 공용화(patterns.md 0·6절) · 요청 이상 코드(dev-rules 단순성) · 인증 소스·데이터 스코프(auth.md 0·4절).

## 절차

1. **대상 diff 확정** — 인자 없으면 현재 브랜치 미커밋 변경.
2. **컨벤션 라우팅** — 변경이 건드린 영역만 dev-rules 라우팅표로 관련 컨벤션 로드(SQL→sql/database, API→api/patterns, 인증→auth …). 프로젝트 CLAUDE.md가 있으면 그 고유 규칙이 우선.
3. **체크리스트화** — 로드한 파일의 STRICT/MANDATORY 항목만 경계별 기준으로. 린트 강제 항목은 뺀다.
4. **읽기 전용 검토** — 범위가 크면 읽기 전용 fan-out. ⚠ 코드 수정 금지, 발견은 보고만. 모든 지적에 `파일:라인` 근거(추측 금지).
5. **백로그 인계** — 발견은 성격에 맞는 ID(`SEC/BE/FE/DB/OPS/DEAD`, 테스트 부재는 `TEST`)로 `docs/REFACTORING_BACKLOG.md`에 추가. templates/backlog.md의 **필수 필드 전부**, 발견 ≠ 완료.

## 출력 형식

- 지적별: 위반 규칙(컨벤션 `파일:절`) + `파일:라인` 근거 + 수정 제안 + 심각도(High/Med/Low)
- 마지막에 **① 확인된 위반 ② 의심 ③ 정상 확인** 3분류 요약

## 범위 한계 (반드시 고지)

정적 diff 검토라 런타임 동작·실DB·동시성은 검증 못 한다 — /paper-test(계약 추적)·qa-claude(파괴)·테스트 실행으로 에스컬레이션.
