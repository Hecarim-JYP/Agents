# 레시피: 부하 테스트 — 오픈 전에 한계와 병목을 숫자로 `[대외]`

> 확정: 2026-10-19 | 원칙: testing.md 0절(**운영 DB 사용 금지**) | 짝: multi-instance.md(커넥션 예산), rate-limit.md(한도), auth.md 1절(비밀번호 해시)
> 부하 테스트의 목적은 "버티는가"가 아니라 **"어디서 먼저 막히는가"**를 찾는 것이다. 대부분은 오류가 아니라 **지연**으로 드러난다 — 오류율만 보면 놓친다.

## 1. 언제 쓰나

대외 서비스 오픈 전, 이벤트·마감처럼 몰림이 예상될 때, 인스턴스 수·커넥션 풀 크기를 정할 때. 사내 시스템은 월말 마감·일괄 처리처럼 동시 사용이 몰리는 화면이 있을 때.

## 2. 결정 항목 (기본값)

| 결정 | 기본값 | 대안 / 비고 |
|---|---|---|
| 도구 | **autocannon**(Node — npm, 스크립트로 시나리오 작성) | k6(시나리오가 복잡할 때) |
| 환경 | **개발 서버 + 개발 DB**, 부하 생성기는 **다른 PC** | 운영 DB 금지(testing.md 0절). 같은 PC에서 부하를 만들면 부하기가 CPU를 나눠 써 결과가 낮게 나온다 |
| 목표 동시성 | **예상 최대 동시 사용자 × 사용자당 초당 요청 × 평균 응답 시간**(동시 처리 중 요청 수) | 3-1절 |
| 합격선 | **p95 응답 시간·오류율을 프로젝트가 정해 CLAUDE.md에 기록** (예: p95 500ms, 오류 0.1%) | 평균값으로 판정하지 않는다 |
| 빈도 제한 | 부하 생성기 IP는 한 곳이라 금방 429 — **테스트 동안 개발 서버 `.env`의 한도값을 올린다**(한도는 설정값으로 둔다) | 우회 헤더 같은 백도어를 만들지 않는다 |

## 3. 표준 설계

### 3-1. 목표 숫자 정하기

- 동시 처리 중 요청 수 = 초당 요청 수 × 평균 응답 시간 (예: 초당 200건 × 0.1초 = 동시 20건).
- 화면 하나가 여는 API 수를 센다(목록 + 코드 + 권한 + 알림 = 4건 등) — "동시 사용자 100명"은 요청 수가 아니다.
- 시나리오는 실제 비율로 섞는다(조회 80 : 저장 15 : 로그인 5 등). 같은 URL 하나만 반복하면 캐시가 모든 것을 가려 실제보다 좋게 나온다.

### 3-2. 커넥션 풀 — 오류가 아니라 대기로 막힌다

실측 2026-10-19 (Express 4.22 + mysql2 3.x + MariaDB 10.11, 쿼리 1건 20ms, 동시 100 요청 8초):

| `connectionLimit` | 처리량 | p50 | p99 | 오류 |
|---|---|---|---|---|
| 5 | 236 req/s | 411ms | 581ms | 0 |
| **10 (mysql2 기본)** | **481 req/s** | **205ms** | **245ms** | **0** |
| 50 | 2,158 req/s | 42ms | 72ms | 0 |

- 처리량 상한 ≈ 풀 크기 ÷ 쿼리 시간 (10 ÷ 0.02초 = 500). 풀이 모자라면 요청이 **풀 대기열에서 기다릴 뿐 오류는 나지 않는다** — p95·p99로만 보인다.
- 풀을 키우기 전에 **커넥션 예산**을 확인한다: 인스턴스 수 × 풀 크기 + 배치·관리 여유 ≤ `max_connections`(MariaDB 11.4 기본 151 — 실측). multi-instance.md 2절.
- 느린 쿼리 하나가 풀을 오래 잡으면 같은 풀을 쓰는 모든 API가 함께 느려진다 — 부하 중 `SHOW PROCESSLIST`로 오래 걸리는 쿼리를 본다(sql.md·database.md 인덱스 규칙).

### 3-3. 비밀번호 해시 — 로그인 몰림이 서버 전체를 멈출 수 있다

실측 2026-10-19 (4 vCPU, Node 22, cost 12, 로그인 동시 20 + 가벼운 API `/api/ping` 동시 5, 8초):

| 구현 | 로그인 처리량 | 로그인 p99 | 그동안 `/api/ping` |
|---|---|---|---|
| `bcryptjs`(순수 JS) | 2.2건/s | 7,319ms | **0 req/s — 서버 전체가 멈춤** |
| **`bcrypt`(네이티브, 스레드풀 4)** | **11.1건/s** | 1,978ms | 5,466 req/s, p99 5ms — 영향 없음 |
| `bcrypt` + `UV_THREADPOOL_SIZE=8` | 12.3건/s | 1,852ms | 2,199 req/s, p99 13ms |

- **순수 JS 해시는 이벤트 루프를 막는다** — 로그인이 몰리는 동안 다른 모든 API가 멈춘다. auth.md 6절 매핑대로 네이티브 `bcrypt`(또는 `argon2`)를 쓴다.
- 로그인 처리량의 상한은 **CPU 코어 수 ÷ 해시 1회 시간**이다 — 스레드풀을 늘려도 코어보다 많으면 거의 늘지 않고 다른 요청만 느려진다(실측). 오픈 이벤트처럼 로그인이 몰리면 인스턴스·코어를 늘리고, 로그인 빈도 제한(rate-limit.md)이 공격성 몰림을 끊는다.

### 3-4. 실행

```js
// load/scenario.mjs — 개발 서버 대상. 토큰은 테스트 계정으로 미리 발급해 환경변수로 받는다(운영 계정 금지)
import autocannon from 'autocannon';

const result = await autocannon({
  url: process.env.TARGET_URL,                      // 예: http://dev-server
  connections: Number(process.env.CONNECTIONS ?? 20),
  duration: 60,
  headers: { authorization: `Bearer ${process.env.TEST_TOKEN}` },
  requests: [{ method: 'GET', path: '/api/orders?page=1&size=20' }],   // 실제 비율로 여러 시나리오를 나눠 실행한다
});
console.log({ rps: result.requests.average, p50: result.latency.p50, p99: result.latency.p99, errors: result.errors, non2xx: result.non2xx });
```

1. 동시성을 단계적으로 올린다(10 → 20 → 50 → 100) — 처리량이 더 이상 늘지 않고 지연만 늘어나는 지점이 한계다.
2. 각 단계에서 서버 CPU·메모리, DB `Threads_connected`·느린 쿼리를 함께 본다.
3. 결과(단계별 처리량·p95·p99·오류, 병목과 조치)를 changelog와 CLAUDE.md에 남긴다 — 다음 테스트의 기준선이 된다.

## 4. 함정 (STRICT)

| 함정 | 증상 | 처방 |
|---|---|---|
| 운영 DB·운영 서버에 부하 | 실사용자 장애 | 개발 서버 + 개발 DB만 (testing.md 0절) |
| 오류율만 보고 합격 | 풀 대기로 p99가 수백 ms인데 "오류 0" (실측) | p95·p99로 판정 |
| 순수 JS 비밀번호 해시 | 로그인 몰림 동안 서버 전체 응답 0 (실측) | 네이티브 bcrypt·argon2 |
| 스레드풀만 늘리기 | 로그인은 그대로, 다른 API만 느려짐 (실측) | 코어·인스턴스 증설 |
| 부하 생성기를 같은 PC에서 | 부하기가 CPU를 나눠 써 결과 왜곡 | 다른 PC |
| 빈도 제한 429를 성능 문제로 오인 | 한 IP의 부하가 한도에 걸린 것 | 테스트 동안 한도값 상향(설정값) |
| URL 하나만 반복 | 캐시 적중으로 실제보다 좋게 나옴 | 실제 비율 시나리오 |

## 5. 스택별 구현

| 구성 | Express | Spring |
|---|---|---|
| 풀 크기 | mysql2 `connectionLimit`(기본 10) — 설정값으로 | HikariCP `maximum-pool-size`(기본 10 — 문서 기준, 이 레시피에서 미실측) |
| 비밀번호 해시 | 네이티브 `bcrypt` (실측) | `BCryptPasswordEncoder`는 요청 스레드에서 돈다 — 톰캣 스레드 수가 동시 해시 상한 (미검증) |
| 부하 도구 | autocannon 7.x (실측) | 동일하게 외부에서 |
